# Sources Host0.3.0 — implementation and release checks

Date:26 November2026. APK implementation commit:
`60e01911bf0c7ba8c2c11e483e5a2fee7e35f72f`.

## Delivered architecture

One app now hosts Anime-Sama+, Sources FR+ and Sources EN+. The generated
catalogue includes eight unique production bundles: Anime-Sama unscoped coverage,
six maintained FR entries, and two independent EN channels sharing their bundle.
No phone-plugin bundle or mapping/resolver policy changed in this release.
All source edits remain in the same maintained `src/`; the APK/host updater loads
those exact + assets rather than Kotlin rewrites.

Four native phone/TV screens separate addon management, shared metadata
credentials, the common HTTPS connection and authenticated engine updates. Each
addon has a stable token, explicit metadata/order/options and scoped pause/delete.
Migration preserves the existing Anime-Sama public addon ID/token, credentials,
SSH identity and LAN/remote-only restriction. A separate8766 loopback ingress
prevents local-only capabilities from being exposed through the shared tunnel.
Unchanged tunnel configuration is retained on settings reload.

Global bounds: two family lookups, three QuickJS contexts (including updater load
checks), six upstream transfers and eight waiting lookups. Existing metadata TTLs
and memory bounds remain; signed media/caption grants stay fresh. No idle polling,
next-episode preload, wake lock, media proxy or URL-argument rewriting was added.

## Playback and subtitle contract

Explicit media `type` is preserved alongside filename hints, including Ani.pm's
extensionless HLS. TV accepts inline captions with headers. Mobile's addon parser
instead loads a Stremio `subtitles` resource. Its opaque filename selector binds
to the addon capability, effective preset, entry and rendition. A fresh subtitle
request runs only that backend and requires a unique matching inventory.
Foreign/missing/ambiguous selectors start no alternative discovery; existing
captions cannot silently switch to another preset after a configuration edit.
No signed caption URL is cached between lookups.

Some Mobile versions ignore external-subtitle headers even in the subtitle
resource. Header-protected captions can still need client support; inline TV
headers and embedded HLS subtitle/audio groups remain intact. This release does
not conceal that limitation with an unrequested proxy.

## Engine delivery

The host pins a separate RSA3072 release public key. Authenticated channel
metadata binds API1/minimum app9, monotonic release sequence, independent family
versions, hashes and immutable tested-commit URLs. Candidate files are bounded,
verified, loaded in real QuickJS, then activated atomically. Running lookups keep
one snapshot; bytecode and retirement are generation/entry scoped. Startup
rehashes/authenticates installed code and retains the APK/previous fallback.
Manual rollback blocks that release until a newer sequence appears. Empty results,
upstream failure and mapping contradictions never cause an automatic rollback.

Startup/on-use checks are nonblocking with a persisted six-hour cooldown; manual
checks bypass the cooldown. Public release1 was signed locally and published.
A real JVM check downloaded the public channel and all eight immutable bundles
through the managed environment's required proxy, verified/loaded them, restored
release1 on restart and rolled back to the APK successfully. Direct egress in this
cloud is unavailable; no environment-specific proxy was added to Android.

Unattended CI signing is prepared but not enrolled: the connector rejected adding
`HOST_ENGINE_SIGNING_KEY` with HTTP403. The private release key remains outside
source/artifacts; local authenticated publishing works. Do not claim every push
will publish an engine update until an administrator completes that secret setup.
See [delivery procedure](../host-engine-updates.md).
